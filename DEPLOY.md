# Публикация: GitHub → Railway → публичная ссылка

Всё, что нужно для деплоя, уже в репозитории: `Dockerfile`, `railway.json`,
проверка живости `/api/health`, CI в `.github/workflows/ci.yml`. Ниже —
путь от папки на компьютере до публичного адреса. Займёт минут десять.

Что будет по адресам после деплоя:

| адрес | что это |
| --- | --- |
| `/` | лендинг Kubix и генератор в пять шагов: набор → фото → кадр → вариант → сборка и PDF |
| `/m` | автономная версия генератора: лента вариантов, переворот картины, PDF — работает с телефона |
| `/lab` | лаборатория алгоритма: все варианты, ручные настройки, сравнение режимов |
| `/api/health` | `{"ok":true}` — по нему Railway проверяет, что сервис жив |

## 1. Код на GitHub

Создайте на GitHub пустой репозиторий (New repository → имя `photo-mosaic`,
**без** README и .gitignore — они уже есть).

**Вариант А — GitHub Desktop (без терминала).**
File → Add local repository → выбрать распакованную папку `mosaic-app`
(в ней уже есть история git) → Publish repository → выбрать созданный
репозиторий. Готово.

**Вариант Б — терминал.**

```bash
cd mosaic-app
git remote add origin https://github.com/<аккаунт>/photo-mosaic.git
git push -u origin main
```

Через минуту на вкладке Actions пройдёт CI: юнит-тесты, сборка автономной
страницы и `next build` — ровно то, что потом сделает Railway.

Загружать файлы через веб-интерфейс GitHub («Upload files») не стоит: в
проекте больше ста файлов, веб-загрузчик столько за раз не принимает.

## 2. Railway

1. [railway.com](https://railway.com) → New Project → **Deploy from GitHub
   repo** → разрешить доступ к репозиторию → выбрать `photo-mosaic`.
2. Railway найдёт `Dockerfile` и `railway.json` и начнёт сборку: `npm ci`,
   `npm run build` (внутри собирается автономная страница и Next), запуск
   `node server.js`. Первая сборка — 3–5 минут, лог виден во вкладке
   Deployments.
3. Деплой считается успешным, когда `/api/health` ответил — это настроено
   в `railway.json`.

Переменные окружения не нужны: `PORT` Railway задаёт сам, сервер его читает.

## 3. Публичный адрес

В сервисе: Settings → Networking → **Generate Domain**. Railway выдаст
адрес вида `https://photo-mosaic-production.up.railway.app` — он публичный
сразу, его можно отправлять тестировщикам. Свой домен подключается там же
(Custom Domain → CNAME по подсказке).

Проверка: открыть `/api/health` (должно быть `{"ok":true,…}`), затем `/` с
телефона — загрузить фото, получить варианты.

## Дальше

- Каждый `git push` в `main` → Railway пересобирает и перезапускает сервис
  (откат на прошлую версию — кнопка Rollback в Deployments).
- Фотографии на сервер не уходят: расчёт в браузере, проекты и выборы
  вариантов — в localStorage пользователя. Серверных данных нет, база не
  нужна.
- Тариф: у Railway есть пробный период, для постоянной публикации
  понадобится платный план — актуальные условия на их странице Pricing.
- Локально то же самое: `npm ci && npm run build && npm start` →
  http://localhost:3000, или `docker build -t mosaic . && docker run -p 3000:3000 mosaic`.
