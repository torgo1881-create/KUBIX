# Отчёт о готовности к production

Дата: 21 августа 2026. Версия: ядро + палитры + лимиты деталей + портреты +
варианты + инструкция + производственная обвязка.

---

## 1. Что готово

### Проверено автоматическими тестами — 164 проверки, все зелёные

| набор | проверок | что покрывает |
| --- | --- | --- |
| `npm test` | 126 | усреднение, LAB и ΔE, палитры, лимиты деталей, лица, варианты, инструкция, PDF, хранилище, API |
| `npm run test:browser` | 38 | два сквозных прогона в Chromium: полный путь и производственная обвязка |
| `npm run test:performance` | 3 | замеры на 32 / 48 / 64 / 96 / 128 |

Ключевые гарантии, каждая закреплена тестом:

- **Цвет ячейки — среднее по её области**, а не центральный пиксель.
- **CIEDE2000 совпадает с 15 контрольными парами Sharma, Wu & Dalal** до 0.0001.
- **Запас деталей не превышается**: после оптимизации `required ≤ available` у
  всех цветов, сумма Required равна числу ячеек.
- **Лицо защищено**: при дефиците деталей с картой весов портится 33.9% важных
  ячеек против 50.2% без неё.
- **Оценка качества воспроизводима**: повторный расчёт даёт те же числа.
- **PDF настоящий**: файл скачивается, открывается pdfjs, 69 страниц, кириллица
  извлекается, блоки идут по порядку.
- **Расчёт не блокирует интерфейс**: 373 мс генерации при паузе главного потока
  96 мс.
- **Сервер не верит клиенту**: whitelist размеров, режимов и палитр, лимиты
  файла и памяти, 429 с `Retry-After`.

### Сквозной путь пройден целиком

Загрузка → кадрирование → настройка → генерация → оптимизация под запас →
выбор варианта → просмотр → статистика → режим сборки → PDF (69 страниц,
1.39 МБ) → PNG (2048×2048) → сохранение проекта. Один тест, один прогон,
без ручных шагов.

### Типы фотографий

Портрет (1 лицо), двое в кадре (2 лица), пейзаж (0), тёмный кадр (0), светлый
кадр (0), низкое разрешение 64×48, животное (0), огромный снимок 5200×3400
(уменьшается автоматически). Ни одного падения, во всех случаях лимиты
соблюдены.

## 2. Известные ограничения

**Firefox и mobile Safari не проверены.** В песочнице доступен только Chromium.
Мобильная вёрстка проверена эмуляцией iPhone-размера (390×844) в Chromium:
горизонтальной прокрутки нет, кнопки крупнее 36 px. Реальный Safari может
отличаться в трёх местах: `OffscreenCanvas` не используется (это плюс),
`navigator.share` ведёт себя иначе, а localStorage в приватном режиме бросает
исключение — последний случай обработан отдельной веткой, но вживую не
проверялся.

**Next-приложение ни разу не запускалось.** Нет сети — нет `npm install`.
TypeScript проходит по всему `src/` без ошибок, вся логика покрыта тестами
через автономную сборку, где работает то же ядро и те же сервисы. Но React-слой
(страница, панель проектов, кнопка отмены) вживую не открывался. Первый
`npm run dev` — за вами.

**Детектор лиц — эвристика, а не нейросеть.** Сегментация кожи в YCbCr плюс
морфология и геометрия. На синтетических изображениях работает уверенно, на
реальных фотографиях будет ошибаться чаще свёрточного детектора: профили,
сильные тени, необычный фон. Интерфейс `FaceDetector` готов к подмене на
MediaPipe или OpenCV одной строкой.

**128×128 не собирается из демо-палитр**: 16 384 ячейки против 11 100 деталей.
Оптимизатор честно возвращает `feasible: false`. В интерфейсе такого размера и
нет — максимум 96×96 (9 216 ячеек), который помещается.

**Фотография не сохраняется** ни в проект, ни в ссылку. Это сознательное
решение: снимок не влезает в localStorage и не должен уезжать в URL. При
открытии проекта восстанавливаются настройки, фотографию нужно выбрать заново.

**Rate limiter живёт в памяти процесса.** При нескольких репликах счётчики не
общие.

**Автономная сборка весит 833 КБ**: в неё вклеены шрифт для PDF (343 КБ) и
копия ядра для Blob-воркера. Для демонстрации приемлемо, но это не способ
доставки продукта.

## 3. Узкие места

| место | цифра | почему |
| --- | --- | --- |
| Оптимизация запаса деталей | 116 мс на 128×128 | самая тяжёлая часть: куча кандидатов и ленивая переоценка |
| Сопоставление с палитрой | ~56 мс на 16 384 ячейки | ΔE00 дорогая, но кэшируется по цветам |
| Четыре варианта | ~2.3 с на 64×64 | считаются последовательно и **на главном потоке** |
| Поиск лица | входит в 700 мс | морфология на маске 192 px |
| PDF | 90 мс на 69 страниц + JPEG | сборка синхронная |
| Память | 41 МБ на 128×128 | матрица «ячейка × цвет» во Float32 |

Главное узкое место — **варианты**: единственная операция, которая всё ещё
подвешивает интерфейс на секунды. Она уже устроена так, что переносится в
воркер тривиально (внутри тот же `computeMosaicCore`), просто не успел.

## 4. Что нужно для масштабирования

**Сразу, до первых пользователей:**

1. Прогнать варианты через воркер — убрать последнюю блокировку UI.
2. Проверить Firefox и настоящий mobile Safari; отдельно — приватный режим.
3. Rate limiter на Redis, если реплик больше одной.
4. Метрики и ошибки: сколько генераций, сколько отмен, где падает.

**Когда появится нагрузка:**

5. Пул воркеров вместо одного на задачу — сейчас воркер создаётся и убивается
   на каждую генерацию (примерно 10–20 мс на старт, при вариантах умножается).
6. CDN для шрифта и статики; для Next — стандартный `next build`.
7. Серверная генерация как опция для слабых устройств: ядро не зависит от DOM
   и запускается в Node как есть — это проверено тестами.
8. Хранение проектов на сервере вместо localStorage, если нужна синхронизация
   между устройствами. Тогда же — настоящий share с фотографией.

**Что не нужно масштабировать:** сам расчёт идёт на клиенте, поэтому нагрузка
на сервер не растёт вместе с числом мозаик. Сервер сейчас — только валидация.

## 5. Что можно дополнительно оптимизировать

**Алгоритмы:**

- Матрица «ячейка × цвет» считается лениво, но хранится целиком:
  `Float32Array(cells × colors)`. Для 128×128 это 786 КБ; можно считать блоками.
- ΔE00 вызывается миллионами раз. Приблизительный предфильтр по ΔE76 с отсевом
  заведомо далёких цветов сократил бы работу в разы без потери качества.
- Карты границ считаются дважды: в ядре и в оценке качества. Их можно
  переиспользовать.
- Оптимизатор запаса пересчитывает соседей на каждый кандидат — кэш на кадр
  сборки дал бы заметный выигрыш.

**Интерфейс:**

- Превью на 32×32 во время настройки — мгновенный отклик до полной генерации.
- Прогресс по блокам вместо этапов — сейчас полоса прыгает.
- Схема блока рисуется элементами (64 штуки на блок) — при 16×16 это 256, всё
  ещё нормально, но canvas был бы честнее.

**PDF:**

- Схемы блоков рисуются прямоугольник за прямоугольником; можно склеивать
  одинаковые соседние ячейки в один прямоугольник — файл станет меньше.
- Потоки не сжимаются. `FlateDecode` через `CompressionStream` уменьшил бы
  файл заметно.
- Шрифт встраивается целиком (343 КБ). Сабсеттинг до используемых глифов дал бы
  примерно 30 КБ.

**Сборка:**

- Автономная версия дублирует ядро ради воркера. Отдельный файл воркера рядом с
  HTML убрал бы дубль, но сломал бы открытие с диска — компромисс сознательный.
